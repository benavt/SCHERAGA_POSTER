# Offline canonical-asset inventory

These small manifests inventory existing frozen model/refold/confidence membership. They are not Zenodo metadata, upload configs, package selections, dataset copies or evidence of a deposition. Source assets remain in their canonical external locations.

Each TSV row uses an `asset_root` identifier from `asset-roots.json` and an actual path relative to that bound directory. The root IDs are logical identifiers, not fictional repository directories. Resolve a file as `private_roots[row.asset_root] / row.relative_path`. The private root dictionary is supplied with the `SCHERAGA_ASSET_ROOTS_FILE` environment variable; it contains a JSON `roots` object mapping IDs to canonical directories. Keep that dictionary outside this repository. Never commit actual machine paths, host bindings or credentials. No payloads are stored here.

`ais-analysis` is the full modeled-chain coordinate file used by the accepted original/refold comparison. `ais-native-source` is the preserved native-source coordinate referenced by the same frozen pair ledger. They are distinct provenance roles and may have identical bytes in separate files. `matched-refold` is the exact joined Boltz2 template-only/no-MSA refold. `confidence-summary` and `residue-plddt` enumerate each joined original summary JSON and pLDDT NPZ. Existing native physicality failures are retained by membership; these files are not a claim that all models passed filters.

The two target datasets each contain 11000 original AIS models across eleven methods and 11000 matched refolds. Adk models have 214 positions; Mad2 is the 1KLQ-derived construct with 197 modeled positions, not a claim of canonical protein length. PDB source CIFs, analysis copies and existing C-alpha comparison copies are separate experimental-reference roles and count as zero AI models. No new coordinates, alignments or scores were generated.

`shared-score-evidence.tsv` applies to both datasets. It lists the original unfiltered 22000-pair TM CSV and shared directional/verification evidence once. Target-only totals exclude these shared files; never count that global table as an 11000-row target table. The shared table was not copied or filtered. Raw evidence and private source ledgers can contain machine paths inside their payloads: this inventory only publishes relative locators and hashes, not payload clearance. Future public packaging requires an explicit privacy review.

`inventory-summary.json` separates model counts, per-role file references/bytes and distinct canonical path totals. Repeated provenance roles can name different copies of identical bytes; a file-row count is not a model count. Shared evidence must be counted once in combined storage totals. SHA-256 values were verified from existing regular files with unchanged before/after identities, within two CPU workers and a four-GiB process limit; private full-path receipts remain outside Git.

Scope is limited to exact existing pair/join/intake membership plus its reference/accepted-score source files. It does not establish completeness of all native generation configs, MSAs, features, PAE matrices, latents, model weights, full reports or run directories. Those were not recursively scanned. No model/output/archive was copied.

Owner-authored files in `zenodo/configs/` are intentionally absent from this work. Missing configs mean stop before packaging. No Zenodo authentication/token probe or HTTP request, DOI reservation, draft creation, upload, publication, GitHub tag or release was attempted. This inventory makes no license, creator, publication-date or access-setting choice. No commits or pushes were made by the inventory task.
